Propositions de stabilisation immediate (pre-v2)

5 actions
  • 1
    render() partiel — observer pattern Ne rebuilder que les rows DOM affectees par une mutation. Utiliser un Map blockId → element DOM. Reduire la charge CPU de 60-80% sur les timelines longues.
  • 2
    Autosave toutes les 3 minutes Via setInterval + IPC Electron (ipcMain.handle('autosave', ...)). Sauvegarde silencieuse dans un fichier .bmb.bak. Notification discrete dans le header.
  • 3
    JSON schema v2 — validation complete a l'import Definir un schema explicite pour le format .bmb. Valider toutes les proprietes a l'import. Migration automatique schema v1 → v2.
  • 4
    Limite taille clips Live Memo Maximum 60 secondes par clip. Avertissement visuel a 45s. Refus d'enregistrement au-dela. Evite les fichiers .bmb de plusieurs Mo.
  • 5
    Tests smoke minimaux Au moins : parseStaffTokens, noteToFreq, normalizeTrackOrder. Script Node.js lance par npm test. Zero dependance framework de test.

2.1 — Lecture audio globale

Priorite haute
Transport global dans le header
Boutons ▶▶ / ▮▮ / ⏹ dans le header. Position de lecture synchronisee avec la timeline (indicateur vertical anime).
BPM et metronome
Champ BPM dans le header. Click metronome optionnel via _pianoNote(). Grille de mesures calculee a partir du BPM.
Lecture synchronisee des clips Live Memo
Tous les clips joues a leur position de mesure respective. Gestion multi-source via Web Audio API (AudioBufferSourceNode). Arret propre de toutes les sources.
Export mixdown
Rendu offline via OfflineAudioContext. Export ArrayBuffer → WAV PCM 16-bit. Telechargement direct (blob URL) ou sauvegarde native Electron.

2.2 — Piste Staff reactivee (solfege complet)

Priorite normale
Insertion au curseur X
Clic sur la portee a la position X insere la note a la mesure correspondante (pas seulement en append a la fin).
Suppression de note
Ctrl+Clic pour selectionner, puis Backspace pour supprimer. Suppression multiple via multiselecti.
Export MIDI
Generer un fichier MIDI type 0 depuis les tokens Staff. Ecriture binaire pure (pas de bibliotheque). Telechargement direct.
Cle de Fa optionnelle
Chaque bloc Staff peut basculer entre cle de Sol (defaut) et cle de Fa (basse). Choix dans le panneau droit.

2.3 — Collaboration

Priorite normale
Export projet partageable
JSON compresse (LZ-String) encode en base64 dans l'URL. QR code generable inline (SVG pur, sans lib). Importable via un simple paste d'URL.
Import depuis URL
Detection automatique du parametre ?p= dans l'URL au chargement. Decode et charge le projet directement.
Mode presentation fullscreen
Vue Railroad animee en fullscreen. Defilement automatique ajustable. Ideal pour repetitions et presentations sur scene.

2.4 — Intelligence musicale

Priorite basse
Detection de tonalite
Analyse des accords Fretboard presents dans le projet. Identification de la tonalite par scoring harmonique (frequence des degres).
Suggestion d'accords coherents
A partir de la tonalite detectee, proposer les accords diatoniques compatibles. Affichage dans le panneau droit lors de l'edition d'un bloc Fretboard.
Transposition globale
Transposer tous les blocs d'un projet d'un nombre de demi-tons choisi. Mise a jour de tous les tokens Staff et diagrammes Fretboard en une operation.

2.5 — UX avancee

Priorite normale
Themes personnalisables
Couleurs par piste configurables. Palettes preset (Dark Classic, Light Wood, Neon Studio). Sauvegarde dans le fichier .bmb.
Zoom horizontal sur la timeline
MEASURE_WIDTH variable de 40 a 160px via slider ou Cmd++ / Cmd+-. Tous les blocs se redimensionnent proportionnellement.
Multi-selection de blocs
Shift+Clic pour ajouter/retirer de la selection. Drag rectangle sur la timeline. Actions groupees (deplacer, supprimer, muter tous les blocs selectionnes).
Templates de projet
Presets : Rock, Jazz, Electro, Acoustique. Chargement du template depuis le dialog Nouveau projet. Structure de pistes et blocs pre-configures.

2.6 — Build & distribution

Strategique
CI/CD GitHub Actions
Build automatique sur push de tag v*. Matrix : arm64 + x64. Artifacts publies dans les GitHub Releases. Zero intervention manuelle.
Notarisation Apple automatique
Secrets GitHub : APPLE_ID, APPLE_TEAM_ID, APPLE_APP_PASSWORD. Notarisation via electron-notarize dans le afterSign hook.
Auto-updater
Integration electron-updater. Verif de mise a jour au demarrage. Dialog de mise a jour non-bloquant. Telechargement en arriere-plan.
Version Windows
Installer NSIS. Signature code Windows (certificat EV). Adaptation des chemins IPC pour Windows. Tests sur Windows 11.

Recommandations architecture v2

L'objectif est de garder la philosophie "un seul fichier HTML" pour la distribution, mais d'organiser le developpement en modules separes compiles a la fin.
#RecommandationJustificationPriorite
1 Extraire JS dans src/app.js index.html depasse le seuil lisible a ~6000 lignes. CSS inline reste acceptable. Haute
2 Module systeme : store.js, render.js, audio.js Separation responsabilites. Permet les tests unitaires sans DOM. Facilite les PR. Haute
3 Versionner explicitement le schema JSON Schema actuellement implicite. Ajout d'un champ "schema": 2 dans le .bmb. Migration automatique. Normale
4 Utiliser contextBridge pour tous les acces Electron Deja fait en v1.5. Maintenir cette rigueur pour toutes les nouvelles fonctionnalites. Fait
5 Bundler optionnel (esbuild) Si modules JS separes, esbuild permet de regenérer un index.html unique pour la distribution navigateur. Zero config, tres rapide. Basse
